# 手势识别系统改进日志

## 2024-XX-XX - 投票机制 + 冷却机制

### 新增功能

#### 1. 多数投票机制
- **目的**：过滤滑动窗口边界的误识别
- **实现**：
  - 维护最近 5 次推理结果的投票缓冲区
  - 只有当某个手势获得至少 3 票时才确认
  - 有效减少瞬时噪声和边界效应

#### 2. 置信度过滤
- **目的**：忽略低质量的推理结果
- **实现**：
  - 设置最低置信度阈值 0.65
  - 低于阈值的预测不参与投票
  - 提高整体识别准确率

#### 3. 冷却机制
- **目的**：防止手势完成后的连续误触发
- **实现**：
  - 确认手势后启动 1.2 秒冷却期
  - 冷却期内忽略所有推理结果
  - 自动清空投票缓冲区
  - **特殊处理**：idle 状态不触发冷却

#### 4. idle 状态特殊处理
- **问题**：原始实现中 idle 永远不会更新到全局状态
- **修复**：
  - idle 投票确认后会更新全局状态
  - 但不启动冷却机制
  - 允许从 idle 快速过渡到其他手势

### 配置参数

```cpp
#define VOTE_WINDOW_SIZE 5      // 投票窗口：5次推理
#define VOTE_THRESHOLD 3        // 投票阈值：至少3次
#define MIN_CONFIDENCE 0.65f    // 最低置信度：0.65
#define COOLDOWN_MS 1200        // 冷却时间：1.2秒
```

### 性能影响

- **内存开销**：+28 字节
- **计算开销**：可忽略
- **延迟**：
  - 投票延迟：100-200ms
  - 冷却延迟：1200ms
  - 总响应时间：~1.3-1.4秒/手势

### 预期改进

| 问题 | 改进前 | 改进后 |
|------|--------|--------|
| 滑动窗口边界误识别 | 经常发生 | 基本消除 |
| 手势完成后误触发 | 经常发生 | 完全阻止 |
| 连续重复触发 | 可能发生 | 完全阻止 |
| 低置信度噪声 | 会触发 | 被过滤 |
| idle 状态更新 | 不更新 | 正常更新 |

### 测试建议

1. **基础测试**：
   - 做清晰的单个手势，验证能正确识别
   - 观察串口输出，确认投票和冷却机制工作

2. **边界测试**：
   - 做快速、短促的手势，验证投票机制
   - 做完手势后立即做另一个，验证冷却机制

3. **参数调优**：
   - 如果误触发多，增加阈值或冷却时间
   - 如果响应慢，减少窗口大小或冷却时间
